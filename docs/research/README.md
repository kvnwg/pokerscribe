# Research folder

Everything decided, measured and learned about PokerScribe's strategy lives here, so it doesn't
depend on any one chat.

| File | What |
| --- | --- |
| [Research report](https://claude.ai/artifact/TuZxQAGj4dUivyWhPjsNYS) | Where strength is lost, the eight research directions, the roadmap with gates |
| `KNOWLEDGE.md` | Principles from the books and papers, in plain words, and where each one is used |
| `baseline_tuning.json` | The frozen baseline agent B0 (26 Nov 2026). Never edited, only added to |
| `experiments.md` | Every experiment: setting, tables, hands, result, standard error, decision |
| `DATASET.md` | Quality, coverage and limits of the hand history dataset (generated by `tools/phh/report.py`) |
| `SCREEN_READING.md` | How the reader reads a poker table, step by step, with what's done and what isn't |
| `DEMO.md` | Notes for a conference demo at Web Summit Vancouver 2027 (proposal, not approved) |

## Rules

1. A change replaces B0 only if it beats B0 by at least 2.5 standard errors on the main table mix,
   loses significantly to no opponent type, and repeats on fresh seeds.
2. Bug fixes for things that are plainly wrong (a misread, folding when checking is free) don't need
   a simulation, but get a regression test.
3. Recorded human or Pluribus actions are observations, never labels of correct play.
4. All testing and automated play stay offline or in environments we own or may use. No auto-play on
   live sites, no detection evasion, no real-money use.

## Roadmap (from the report)

| Phase | Work | Gate before the next phase |
| --- | --- | --- |
| 0 | Correct inputs (blinds, pot, bets), capture log for replay tests, frozen B0 | No misread-driven all-ins in replay tests; B0 rebuilds exactly |
| 1 | Duplicate deals, AIVAT-style luck adjustment, held-out opponents, weakness report | Standard error per comparison at least halved |
| 2 | River CFR solver, push-or-fold equilibrium, adaptive time budget, solver-labelled data | Matches closed-form results; beats B0 by 2.5 SE; p95 under 400 ms |
| 3 | Bayesian opponent model with HandHQ priors, robust exploitation | 5% lower log-loss on held-out days; no loss against B0 |
| 4 | Pluribus-style blueprint (Monte Carlo CFR in a compiled engine) and depth-limited search | Beats the Phase 3 agent by 2.5 SE; exploiters win less |
| 5 | Deep CFR or ReBeL-style value networks, only if Phase 4 shows abstraction is the limit | Beats the Phase 4 agent at equal or lower decision time |
